#Creating composable templates
Composable index templates let you abstract common settings, mappings, 
and aliases into a reusable building block called a component template.

PUT _component_template/component_template_ex1
{
  "template": {
    "mappings": {
      "properties": {
        "@timestamp": {
          "type": "date"
        }
      }
    }
  }
}

PUT _component_template/component_template_ex2
{
  "template": {
    "mappings": {
      "properties": {
        "ip_address": {
          "type": "ip"
        }
      }
    }
  }
}

#Why the Alias Matters
#When ILM rolls over, it:

Creates the new index (mylogss-000002)
Moves the write alias (mylogs_alias) to point to the new index
Marks the new index as is_write_index: true

If you write directly to mylogss-00001, ILM can still roll it over based on the conditions being met. 
But the real problem comes after rollover:

Your next writes keep going to mylogss-00001 (now a read-only historical index)
mylogss-00002 gets created but receives no new data
Your subsequent rollovers (00002 → 00003) will never trigger because 00002 stays empty

The Alias is the "Moving Pointer"
Before rollover:         After rollover:
                          
mylogs_alias             mylogs_alias
     │                        │
     ▼                        ▼
mylogss-00001  ──────►   mylogss-00002  (new writes)
                         mylogss-00001  (frozen, searchable)
If you bypass the alias, that pointer never moves and the whole lifecycle breaks down silently — no errors, 
just stale data accumulating in the wrong index.

#Always write to the alias, never the index directly. The alias is the only thing that keeps rollover working end-to-end.

#With datastream

No Alias Management Needed
With a data stream, you never create the write alias or manage is_write_index yourself. 
The data stream handles all of that internally. You just write to the data stream name directly

PUT _data_stream/mylogss

But template needs to support data stream

PUT _index_template/temp-02
{
  "index_patterns": ["mylogss*"],
  "priority": 1,
  "data_stream": {},        // ←  required
  "template": {
    "settings": {
      "number_of_shards": 3,
      "index.lifecycle.name": "mylogspolicy"
      // ← no rollover_alias needed here either
    }
  }
}
